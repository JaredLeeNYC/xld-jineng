# 技能矩阵系统一期规格

Status: ready-for-agent

## Problem Statement

工厂目前缺少一套简单、统一且可追溯的技能管理工具。管理人员难以快速回答“员工会什么、岗位要求什么、谁还不达标、谁需要培训、哪些技能即将到期”，员工也缺少查看个人技能档案和完成培训任务的统一入口。

现有需求材料覆盖了人员、岗位、技能、教材、培训、考试、评定、矩阵、统计和多种外部集成，但若一期全部实现，会演变成复杂的人力资源与在线学习平台，增加实施和使用负担。工厂一期真正需要的是一个可上线、可持续维护的最小管理闭环：定义岗位技能要求，安排并确认培训，完成技能评定与归档，自动更新员工技能档案和技能矩阵，并通过清晰指标发现差距和到期风险。

## Solution

建设一套单工厂、单租户、云端独立部署的响应式 Web 系统。员工、部门主管、HR/培训管理员、高层查看者和系统管理员使用同一系统，但看到符合各自职责的数据与操作。

系统以岗位技能要求为管理基准。员工可在手机或电脑上查看培训资料、提交培训完成和查看个人技能；培训负责人或主管确认后形成正式培训履历。评定人在线下完成考核后录入结果，部门主管确认，HR 归档生效；只有归档通过且仍在有效期内的评定才能形成员工当前技能并参与矩阵达标计算。

一期提供组织人员 Excel 导入、轻量培训资料库、培训双确认、固定技能评定流程、技能矩阵、四类核心指标、Excel 导出、站内通知、企业微信群 Webhook、审计日志和云端部署。在线考试、扫码签到、动态审批、自定义报表和真实 MES 同步留待二期根据上线反馈决定。

## User Stories

1. As an 员工, I want 使用工号和密码登录, so that 我可以进入自己的技能与培训空间。
2. As an 员工, I want 首次登录时修改初始密码, so that 我的账号不会长期使用统一初始凭证。
3. As an 员工, I want 在手机浏览器顺畅使用系统, so that 我无需安装 APP 就能在现场完成任务。
4. As an 员工, I want 查看我的待培训和退回任务, so that 我知道下一步需要做什么。
5. As an 员工, I want 打开或下载培训资料, so that 我可以完成自主学习。
6. As an 员工, I want 提交培训完成并附加必要说明, so that 培训负责人可以进行正式确认。
7. As an 员工, I want 查看任务被退回的原因, so that 我可以补充材料后再次提交。
8. As an 员工, I want 查看我的正式培训履历, so that 我能够确认哪些培训已被认可。
9. As an 员工, I want 查看我的当前技能、能力等级和有效期, so that 我了解自己的能力状态。
10. As an 员工, I want 对照当前岗位要求查看技能差距, so that 我知道需要提升哪些能力。
11. As an 员工, I want 查看技能评定结果和整改建议, so that 我可以按要求改进。
12. As an 员工, I want 收到培训任务、退回、评定结果和到期站内通知, so that 我不会遗漏重要事项。
13. As a 部门主管, I want 查看本部门的岗位技能达标率, so that 我可以掌握部门能力风险。
14. As a 部门主管, I want 查看本部门技能覆盖率, so that 我可以发现关键岗位是否缺少合格人员。
15. As a 部门主管, I want 按岗位、员工和技能下钻矩阵, so that 我能定位具体差距。
16. As a 部门主管, I want 创建面向本部门的培训计划, so that 我可以组织针对性提升。
17. As a 部门主管, I want 为培训计划选择岗位、人员和资料, so that 培训任务能准确分配。
18. As a 部门主管, I want 查看员工提交的培训任务, so that 我可以确认实际完成情况。
19. As a 部门主管, I want 批量确认集中培训的实际参训人员, so that 现场培训记录可以高效归档。
20. As a 部门主管, I want 上传签到表、照片或培训记录作为证据, so that 完成确认有依据。
21. As a 部门主管, I want 退回证据不足的培训提交并说明原因, so that 正式履历保持可信。
22. As a 部门主管, I want 确认或退回本部门技能评定, so that 评定结果经过业务负责人审核。
23. As a 部门主管, I want 只管理本部门数据, so that 部门间个人信息不会越权暴露。
24. As an HR/培训管理员, I want 维护部门和岗位, so that 组织结构与工厂实际一致。
25. As an HR/培训管理员, I want 通过 Excel 批量导入员工, so that 首次上线不需要逐人录入。
26. As an HR/培训管理员, I want 在导入前看到逐行校验结果, so that 错误数据不会写入正式库。
27. As an HR/培训管理员, I want 使用工号、部门编码和岗位编码识别重复或无效数据, so that 批量导入可重复且可纠错。
28. As an HR/培训管理员, I want 记录员工岗位变更和生效时间, so that 历史任职关系可追溯。
29. As an HR/培训管理员, I want 停用离职员工或不再使用的基础数据, so that 历史记录保留但不再用于新业务。
30. As an HR/培训管理员, I want 创建通用、专业和核心三类技能项, so that 技能属性清晰统一。
31. As an HR/培训管理员, I want 使用固定 0-4 能力等级, so that 不同部门的矩阵可以比较。
32. As an HR/培训管理员, I want 为岗位配置必备技能和要求等级, so that 系统能够自动判断达标与差距。
33. As an HR/培训管理员, I want 复制岗位技能要求并批量调整, so that 相似岗位可以快速配置。
34. As an HR/培训管理员, I want 设置技能是否需要复评及默认有效期, so that 到期管理符合技能风险。
35. As an HR/培训管理员, I want 上传 PDF、Word、PPT 和图片资料, so that 常用培训内容可以集中使用。
36. As an HR/培训管理员, I want 为培训资料配置外部视频或网页链接, so that 系统无需承担视频平台能力。
37. As an HR/培训管理员, I want 停用过期资料但保留历史引用, so that 旧培训记录仍可审计。
38. As an HR/培训管理员, I want 创建、编辑、发布、取消和结项培训计划, so that 培训全过程有统一状态。
39. As an HR/培训管理员, I want 发布计划时自动生成每名员工的培训任务, so that 执行进度可以逐人追踪。
40. As an HR/培训管理员, I want 查看全厂培训完成率和逾期任务, so that 我可以推动未完成事项。
41. As an 评定人, I want 录入线下笔试、实操或综合评审结果, so that 线下考核能够进入系统闭环。
42. As an 评定人, I want 记录能力等级、通过结论、证据、原因和整改建议, so that 评定结果完整可追溯。
43. As an HR/培训管理员, I want 归档已经主管确认的评定, so that 正式技能档案由 HR 最终把关。
44. As an HR/培训管理员, I want 退回信息不完整的评定, so that 归档结果保持可信。
45. As an HR/培训管理员, I want 作废错误的已归档评定并重新发起, so that 正式历史不可篡改但可以纠错。
46. As an HR/培训管理员, I want 发起技能复评, so that 即将到期或已过期技能可以重新生效。
47. As an HR/培训管理员, I want 查看全厂技能矩阵, so that 我可以进行人员技能盘点。
48. As an HR/培训管理员, I want 按部门、岗位、员工和技能筛选矩阵, so that 我可以定位具体管理问题。
49. As an HR/培训管理员, I want 导出与当前筛选一致的 Excel, so that 线下汇报使用同一数据口径。
50. As an HR/培训管理员, I want 查看岗位技能达标率, so that 我知道必备要求的满足程度。
51. As an HR/培训管理员, I want 查看部门技能覆盖率, so that 我知道关键岗位技能是否有人覆盖。
52. As an HR/培训管理员, I want 查看培训任务完成率, so that 我可以衡量培训执行情况。
53. As an HR/培训管理员, I want 查看未来 30 天到期和已经过期的技能数量, so that 我能提前安排复评。
54. As a 高层查看者, I want 只读查看全厂 Dashboard、矩阵和导出, so that 我能掌握全厂能力状况而不会误改数据。
55. As a 系统管理员, I want 创建和维护五类固定角色账号, so that 系统权限简单且可控。
56. As a 系统管理员, I want 重置员工密码并强制旧会话失效, so that 账号问题可以安全处理。
57. As a 系统管理员, I want 查看账号锁定和登录记录, so that 异常访问可以被发现。
58. As a 系统管理员, I want 配置并测试一个或多个企业微信机器人 Webhook, so that 管理群可以收到外部提醒。
59. As a 系统管理员, I want 查看 Webhook 发送成功、失败和重试记录, so that 外部通知问题可以排查。
60. As a 系统管理员, I want 对失败的 Webhook 消息进行幂等重试, so that 重试不会重复产生业务记录。
61. As a 系统管理员, I want 查询关键业务操作的审计日志, so that 培训、评定、停用和导出可以追溯。
62. As a 系统管理员, I want 查看数据库与迁移是否就绪, so that 发布后可以可靠判断服务可用性。
63. As an 外部系统维护者, I want 未来通过稳定业务编码和版本化集成边界对接, so that MES 集成不需要直接写核心表。
64. As an 运维人员, I want 使用与 IoT 项目一致的显式云端发布流程, so that 发布、回滚和验收方式保持统一。
65. As an 运维人员, I want 数据库和附件分别得到备份与恢复验证, so that 业务证据不会因只备份数据库而丢失。

## Implementation Decisions

- 产品采用单工厂、单租户、独立部署；不增加工厂或租户字段，其他工厂使用另一套部署。
- 工程采用 Bun workspace，包含响应式 Web、Elysia API、配置包、Drizzle 数据库包和共享契约包。
- 不复制参考项目的 IoT 业务应用；MQTT、EMQX、采集、遥测、设备、计算指标和边缘适配器全部排除。
- Web 使用 React、Vite、TanStack Router/Query/Form/Table、Tailwind 和统一 UI primitives。
- API 使用 Elysia 与 OpenAPI，响应统一为成功数据或结构化错误 envelope。
- service 拥有业务规则并返回业务结果，route 只处理鉴权、输入、状态码和协议映射。
- PostgreSQL 是唯一业务数据库，Drizzle 管理 schema 与迁移；关键跨表状态流转必须使用事务。
- 主键使用内部 UUID；工号、部门编码、岗位编码和技能编码是导入、导出及未来集成的稳定业务键。
- 固定角色为员工、部门主管、HR/培训管理员、高层查看者和系统管理员，不提供角色设计器。
- 员工使用工号登录；密码使用安全加盐哈希，session token 仅以 hash 存储在数据库并通过 HttpOnly cookie 传递。
- 首次登录必须改密；连续失败触发临时锁定；管理员重置密码后旧会话立即失效。
- 权限同时包含动作权限和数据范围；员工只访问本人，主管只访问本部门，高层只读。
- 部门、岗位、员工、技能项、岗位要求、资料和账号仅允许启用或停用。
- 已发布培训、正式培训履历、技能评定、归档和通知发送记录不得物理删除；纠错使用取消、退回、作废或新记录。
- 技能类别固定为通用、专业和核心；能力等级固定为 0 未掌握、1 了解、2 可独立操作、3 熟练并可指导、4 专家。
- 岗位技能要求包含要求等级和是否必备；同一岗位与技能项只能存在一条当前有效要求。
- 当前员工技能是归档评定的查询快照，历史事实以技能评定为准。
- 培训计划状态为草稿、已发布、进行中、已完成、已取消；发布时固化人员范围并生成员工任务。
- 培训任务状态为已分配、已提交、已确认、已退回、已取消；逾期是计算标记而非生命周期状态。
- 员工提交不能形成正式培训履历；只有培训负责人或主管确认后才计入完成率。
- 评定结论与流程状态分离。流程为草稿、待主管确认、待 HR 归档、已归档、已退回、已作废。
- 只有通过、已归档、未作废且仍在有效期内的评定才能形成员工当前有效技能。
- 培训完成不能自动授予技能；失败评定可归档但不产生当前技能。
- 技能到期前 30 天标记即将到期；到期或作废技能保留历史但不计入达标与覆盖。
- 技能矩阵、技能差距和四类指标是基于事实表的查询视图，不建立可人工编辑的矩阵或报表实体。
- 岗位技能达标率只统计必备岗位技能要求；员工有效等级大于等于要求等级时达标。
- 部门技能覆盖率按至少一名当前在岗员工达标的必备岗位-技能组合计算。
- 培训完成率只把已确认且未取消的任务计入分子。
- 培训资料支持受控类型的文件上传和外部链接，不实现视频转码或复杂版本树。
- 附件由对象存储适配器管理；数据库仅保存元数据和业务关联。开发及一期生产使用发布目录之外的持久化挂载目录，并纳入独立备份。
- 站内通知面向具体用户；企业微信 Webhook 仅用于管理群外部提醒。
- 通知事件通过持久化 outbox 发送；Webhook 失败不回滚培训、确认或归档，失败记录可幂等重试。
- 一期使用单 API 实例内的定时任务处理到期扫描和 outbox，不部署空壳 worker。
- 企业微信 Webhook 地址只接受安全 HTTPS 外发地址，凭证和完整地址不得进入日志。
- Excel 导入先 dry-run 校验并返回逐行错误，确认后再执行事务性导入；重复工号不得产生重复员工。
- Excel 导出必须复用页面筛选条件与指标计算逻辑。
- 所有桌面列表使用服务器分页表格，手机使用卡片视图，并提供独立 loading、error 和 empty 状态。
- 员工移动首页优先展示待培训、退回任务、即将到期技能和个人技能，不直接缩小管理后台。
- 高层查看者复用只读 Dashboard、矩阵和报表页面，不复制业务页面。
- 未来 MES 集成通过内部 port、稳定业务键、幂等字段和版本化命名空间隔离；一期不实现同步任务或空同步页面。
- API 提供独立 health 与 ready 检查；ready 必须校验数据库连接和迁移一致性。
- 云端发布沿用 Nginx 同源托管、systemd API、Docker Compose PostgreSQL、显式 migration、固定发布版本、回滚和 readback。
- 数据库备份与附件备份是两个独立的可恢复对象；上线前必须验证恢复读回。

## Testing Decisions

- 测试只验证外部可见行为、权限结果、状态变化、数据不变量和 API 契约，不断言内部函数调用或组件实现细节。
- 主要测试接缝是 Elysia `app.handle(Request)` 级 HTTP 集成测试，连接任务隔离的 PostgreSQL，覆盖认证、权限、事务、状态流转、指标和导出。
- 每个测试拥有明确的测试数据库所有者与清理边界，不共享开发、预发布或生产数据库。
- 纯计算模块单独测试，包括能力等级比较、有效期状态、四类指标、Excel 行校验和通知模板渲染。
- 关键 schema、唯一约束、迁移一致性和事务回滚使用真实 PostgreSQL 合同测试。
- Web 只为高价值交互编写测试，不大量测试样式和普通列表实现。
- 少量浏览器端到端测试覆盖登录、员工培训双确认、评定三级确认、矩阵更新、Webhook 故障隔离和越权拒绝。
- API 测试沿用参考架构的成功/失败 envelope、严格 OpenAPI response schema、服务器分页和 `app.handle(Request)` 模式。
- 响应式验收至少覆盖桌面管理表格和手机员工卡片两种视口。
- 上传测试覆盖允许类型、大小限制、权限、孤儿清理和下载授权，不依赖真实云对象存储。
- Webhook 测试使用可控 fetch 替身，验证成功、非零错误码、网络失败、幂等重试和业务事务不回滚。
- Excel 导入测试覆盖 dry-run、重复工号、无效部门/岗位、整批确认和错误行不污染正式数据。
- 主交付门禁是 `bun test` 与单一 `bun run check`；类型检查、lint、OpenAPI 生成和关键部署脚本校验纳入 check。
- 上线验收使用至少 50 名员工和 3 个岗位，五类角色走完真实闭环并连续试运行一周。

## Out of Scope

- 在线考试、试题库、题型、组卷、自动阅卷、防作弊和线上成绩。
- 原生 APP、企业微信小程序、扫码或刷卡签到、断网同步。
- SSO、企业微信身份登录、短信和邮件找回密码。
- 企业微信按员工个人精准推送；一期只向管理群发送外部提醒。
- 动态审批流、审批设计器、五日超时升级、联合决策和系统内调岗决策。
- 自定义角色、逐项权限设计器、自定义技能分类和自定义等级体系。
- 复杂教材版本树、视频转码平台、精细下载权限和使用频次分析。
- 自定义报表、雷达图、人才画像、人才推荐和预测分析。
- HRIS、ERP、MES 或 PPS 的实际同步、回调和管理页面。
- 多工厂、多租户、集团汇总和工厂切换。
- 电子签章、数字签名和多语言界面。
- 完整岗位技能标准版本发布系统。
- 培训预算、反馈问卷、证书自动生成和独立证书库。
- 图片格式报表导出；一期只交付 Excel 导出。
- 复杂阈值预警；一期只处理任务逾期、技能即将到期和已过期。

## Further Notes

- 一期必须保持“培训完成、评定通过、当前有效技能”三个概念独立，任何实现都不得通过培训确认直接更新技能矩阵。
- 规格应通过纵向能力票据实施，每张票据同时包含必要的 schema、service、API、UI 和自动化验收，不按前端、后端、数据库横向拆分。
- 推荐纵向顺序为：五角色骨架；组织与岗位技能；初始矩阵；资料与培训双确认；评定与矩阵更新；有效期与通知；指标与导出；审计部署与上线验收。
- 一期验收场景包括数据初始化、员工自学、集中培训、评定归档、不通过与退回、复评与到期、Webhook 故障、角色越权、指标导出一致和一周试运行。
- 系统以简单、可用、可追溯为优先级；任何“为未来预留”的设计不得提前引入租户、工作流、考试或同步平台复杂度。
