# 10 — 完成审计、部署与上线验收

**What to build:** 系统可以按与 IoT 项目一致的受控方式发布到云端，管理员能追溯关键操作，运维能备份和恢复数据库及附件，项目团队能用 50 名员工和 3 个岗位完成一周试运行验收。

**Blocked by:** 08 — 处理有效期、站内通知与企业微信群提醒；09 — 交付 Dashboard、指标与一致 Excel 导出

**Status:** ready-for-go-live

- [x] 审计查询覆盖登录安全事件、基础数据变更、岗位变更、培训发布与确认、评定流转、停用、作废、导出和通知重试。
- [x] 审计记录包含操作者、动作、对象、时间和必要摘要，不记录密码、密钥或完整 Webhook。
- [x] 云端发布使用 Nginx 同源托管、systemd API、Compose PostgreSQL、固定版本和显式触发，不因普通主干 push 自动生产发布。
- [x] 发布前检查迁移一致性；有 schema 变化时执行有备份、授权、readback 和回滚步骤的显式迁移。
- [x] health、ready、OpenAPI、登录、数据库和静态 Web 在发布后完成自动读回。
- [x] 数据库与附件执行独立备份，恢复演练能从备份重建可登录且可下载证据文件的系统。
- [x] 使用至少 50 名真实或脱敏员工和 3 个岗位完成初始化。
- [x] 五类角色完成“发布培训、员工提交、负责人确认、评定、主管确认、HR 归档、矩阵更新”全链路。
- [ ] 企业微信完成真实测试发送，失败重试和站内通知均有验收证据。
- [x] 形成一周试运行清单、阻塞问题判定标准、操作部署说明和最终验收记录。

现场待办：生产企业微信群实发证据与连续一周无阻塞试运行只能在获批云环境中执行，验收模板保持待填写，未以替身测试冒充生产完成。
