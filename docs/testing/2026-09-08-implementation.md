## QA 第一轮返修：HTTP 主管角色

- QA指出：主代理集成时role请求字段误加登录schema，员工创建schema遗漏role，导致UI虽选择主管但接口清洗字段后创建普通员工。
- 已修复：登录不接收role；POST /api/organization/employees接受employee/department_manager；清理培训资料接口误加的trainingType，培训类型仅留培训计划。
- 回归证据：postgres-contract新增真实HTTP请求创建主管，并SQL读回role=department_manager与性别/年龄/司龄/学历；2026-09-08 `bun run check`通过，零lint/type警告、真实PostgreSQL合同和前端构建通过。
- 等待独立QA浏览器重验，不以开发自验替代最终结论。
