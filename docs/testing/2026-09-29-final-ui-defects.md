# 最终 UI 独立验收缺陷

## QA-UI-01 管理员通知入口导向无权限页面（P2）

- 复现：在隔离本地环境，以 `ADMIN001` 正常登录；点击顶部“通知”。
- 实际：进入通知页面后，服务端返回 HTTP 403，`FORBIDDEN` / “系统管理员无业务通知”；无法展示消息通知列表。
- 预期：角色没有业务通知权限时，不展示该入口，或明确指向有权限的通知配置页面；不能放宽服务端业务通知权限。
- 影响：1440、390、320 三种宽度均能进入错误页面。
- 证据：`2026-09-29-final-ui-round1-evidence.json` 的三条 ADMIN001 失败；`apps/server/src/notification-service.ts` 的 `list` 明确拒绝 `system_admin`。
- 处理：已退回主开发智能体修复，按 `system_admin` 隐藏通知入口，服务端权限不变。独立真实 Chrome 在 1440/390/320 三种宽度复测均通过；管理员审计入口与账号导航仍正常；员工 Bell 与工作台三个真实入口也正常。
- 关闭证据：`2026-09-29-final-ui-evidence.json`，最终 13 项全部通过。原始红色证据保留在 round1 文件。

同轮员工手机断言因顶部位置文本在窄屏按设计隐藏，`innerText` 不含该文本而误报；页面实际已进入消息通知。改用页面可见标题验证，并将当前状态文本读取改为 `textContent`。此项为测试脚本修正，不是产品缺陷。
