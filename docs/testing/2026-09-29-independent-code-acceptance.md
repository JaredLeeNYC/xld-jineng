## 静态代码检查

- `training-repository.ts`：新增负责人条件仅位于计划列表读取 SQL。账号必须启用且员工 ID 在该计划负责人数组中。编辑/提交/逻辑删除仍要求 HR 或创建人；审批仍检查独立审批人、全部负责人及对象的部门范围；任务执行仍检查指定负责人和员工部门关系。`factoryRead` 的角色替换只用于列表读取，更新工作流继续使用真实角色。
- 未发布预估人数使用有效员工及当前有效目标去重计算，不依赖浏览者的员工列表。发布后前端继续使用任务人数。
- `training-analytics-service.ts` 强制普通主管采用账号部门；仓库人数、计划参与人数与实际任务查询同时应用部门和区域条件。不能用其他部门区域绕过本部门读取边界；区域下没有有效对象的未发布计划不进入列表，发布记录保留历史参与者。计划和实际使用原有独立日期口径，取消计划不纳入汇总。
- `assessment-repository.ts` 对区域采用左连接，无区域启用状态过滤；未分配区域不会丢弃评定，停用区域名称仍可读取，原评定角色和部门条件不变。界面从评定记录生成区域选项，因此历史停用区域仍能筛选；变更部门会清空区域和员工条件，变更区域清空员工条件。
- 组织人员的部门与区域、岗位、员工由互斥状态分别渲染。切换时关闭编辑及历史弹层。技能目录和岗位要求同样互斥渲染；岗位部门筛选逻辑保留。
- 培训工作区默认年度汇总，计划、任务和资料独立挂载；概况通过 `showPlanDetails={false}` 隐藏计划明细。年度加载使用 AbortController 与错误、空态处理，月份按北京时间开始月份过滤。
